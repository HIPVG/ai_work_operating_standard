## 使い方

1. 正本と案件の指示・権限を先に読む。
2. 必要ならHTML又はカタログで候補を探し、テンプレート本文と既存帳票への統合先を確認する。
3. 採用した問い・統合先と、判断に影響する未解決事項を案件の既存記録へ残す。未選択の50文書すべてに不採用理由の記入を求めない。
4. 権限、費用、範囲、法的適合、受入の判断は、この補助資料からは行わない。

テンプレート選択補助のHTMLは単独ファイルで開ける。質問への回答から候補をページ内で計算する。外部通信や自動保存は行わない。保存ボタンから候補一覧をJSON／CSVファイルにできる。再読込で画面の回答は初期化される。

## テスト方針の文案を作る

公開対象の編集元・利用用HTMLは `test-policy-builder.html` の一つで、運用標準v1.6に対応する。G0又はG5を選び、必要な前提を入力して「文案を作成」を押す。文案は画面で編集でき、現在の文案をコピー又はMarkdownでダウンロードできる。入力変更だけでは文案を上書きせず、再作成は明示操作で行う。外部送信・自動保存・保存済み文案の読込みは行わない。再読込すると入力と編集内容は消える。

検査対象の空欄・選択矛盾がなくても、内容、証拠、許可・上限は未照合である。試験件数、工程通過、受入、安全性及び実行許可を自動判定しない。G5の文案は見積りと許可上限を区別し、未達の処置を既存カードへ接続する。文案だけで計画が確定したとは扱わない。

DrawIOの「現行・処理フロー（v1.6）」が現在の説明である。「旧案・レビュー注記」は改訂経緯として保持しており、旧版のTXT保存等の説明は現行仕様ではない。別版HTML、バックアップ及びPNGは作業資料として保持し、今回の公開対象に含めない。公開対象の一覧は[公開候補一覧](publication-scope-v1_6.json)、確認結果と制限は[v1.6改訂記録](CHANGE_RECORD_v1_6_2026-10-07.md)を参照する。

コードの変更後は `node support/verify-test-policy-builder.cjs` で文案生成とDOM代替物によるイベント処理を確認する。この検査は実ブラウザの表示、クリップボード、保存先のファイルを確認するものではない。

## 候補一覧を保存する

質問とLoose／Medium／Tightを選んだ後、「候補一覧をJSONで保存」又は「候補一覧をCSVで保存」を押す。現在の候補文書、役割、選ばれた理由、統合先、文書への相対パスに、回答条件・確認の詳しさ・作成日時・ツール版を添えて保存する。JSONはほかのツールへの受け渡しに、CSVは表計算ソフトでの閲覧に使える。

保存するのは現在の候補一覧であり、折りたたみの候補外・回答待ち文書やテンプレート本文は含まない。分からない回答もそのまま残る。保存先はブラウザのダウンロード設定に従う。この版には保存した回答を画面へ読み戻す機能はない。

## 条件と厚みの関係

16問には具体的な3段階の回答と「未確認」がある。Given Conditionsは関係する論点を、Loose／Medium／Tightはその論点を記録・確認する厚みを表す。人数・規模・リスク区分から厚みを自動認定しない。候補件数はどの厚みでも回答によって変わる。強い条件が多ければLooseでも多数の候補が出る。

候補、確認を厚くすると候補、条件未確認、現回答では候補外の4区分で全50件の位置付けを表示する。3段階のどれにも、全件作成義務や固定件数はない。利用の詳細と改版手順は[ハンドブック](OPERATIONS_HANDBOOK.md)を参照する。

編集元は[選択ルール](selector-rules.json)、[画面ソース](selector-page.html)、[選択処理](selector-engine.js)。カタログと利用用HTMLは[生成手順](build-selector.cjs)で同期する。[検証手順](verify-selector.cjs)は条件・厚み・50件の到達性を確認する。
