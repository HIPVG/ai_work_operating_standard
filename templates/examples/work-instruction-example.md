## 位置付け

作業カードの8項目は運用標準9.1、記述方法と例の扱いは9.4・9.5に従う。本例は、項目の意味を保持したまま、目的、行動、証拠、継続・停止の関係を書くための参考である。例の対象、権限、数値、工程、結論を実案件へ転記しない。未指定の事実を例から補わない。

## 一枚のカードを実行指示文で書く例

以下はすべて架空の条件である。責任者Aの依頼EX-REQ-01 v1は、指定の文書案を作成・自己確認する範囲だけを許可している。実行者Bはこの条件下で次の指示を受ける。

> 今回は、EX-REQ-01 v1の文案受入条件に対応し、受入責任者Aが記録の欠落時の扱いを判断できるように、提供済み資料に基づく説明文案を作成してください。製品の実装、実際のデータ調査、製品全体の受入は今回の目的に含めません。
>
> 対象は指定された文書案の「欠落時の表示」節です。入力はEX-REQ-01 v1と提供済み項目表EX-DATA-01 v1であり、この版の記載を確認済みという架空条件です。入力にない実画面の挙動は未確認として扱ってください。他の節と製品コードは対象外です。
>
> Aは目的・着手・文案の受入を決める人間の責任者です。Bには、上記入力の読取り、指定節の編集、その内容と入力の照合が許可されています。指定先への書込みが可能であることも、この例の前提です。外部送信、追加資料の取得、コード編集、モデル変更、新規課金は許可されていません。入力と作成先以外へアクセスしないでください。
>
> 今回解消する阻害条件は、文案で欠落時の扱いを区別できないことです。解消後は直ちに、以下の文案受入条件と入力を照合してください。文案には、入力で確認できる記録がある場合と、必要な記録が欠落する場合を分けて記述してください。欠落を成功と表示しないこと、未確認を事実として補わないことを受入条件とします。文案の該当箇所を入力の該当箇所へ対応付け、Bによる自己確認として結果を同じカードへ記録してください。これは実画面の動作確認ではありません。
>
> 入力に矛盾があり表示方針を決められない場合は、その箇所の確定を止め、根拠と選択肢をAへ渡してください。矛盾のない箇所の整理は許可範囲で継続できます。指定外の編集又は費用が必要になった場合は、該当操作を開始せず判断を求めてください。差戻しは保存した前版へ戻せる範囲で行い、他者の変更を戻さないでください。
>
> 着手前の結果は「未実施」です。作成後は文案の版、条件ごとの自己確認結果、入力の参照箇所、未解消の事項を追記してください。文案の受入条件を満たしたら、Aの受入判断に必要な結果を提示してこの依頼を閉じる準備へ進んでください。実装や公開は始めません。

### 8項目との対応

| 9.1の項目 | 上の指示文で保持する内容 |
|---|---|
| 目的と期待結果 | Aの判断に使う文案、非目的、観測可能な到達点 |
| 対象と現状 | 指定節、入力版、確認済み範囲、実画面は未確認 |
| 決定・受入責任者 | Aの決定権と受入対象 |
| 許可・禁止と費用 | 読取・指定編集・照合、対象外操作、新規課金なし |
| 主体と権限 | B、入力と作成先、例における権限確認の前提 |
| 検証と証拠 | 受入条件別の入力照合、参照箇所、自己確認の限界 |
| 停止・復旧 | 矛盾する確定・対象外操作の停止、許可内継続、前版保存 |
| 結果と残課題 | 着手前は未実施、実施後に版・結果・残件を追記 |

この例のBの自己確認は独立確認ではない。実案件でAIを指示作成・実施へ使う場合は運用標準6.13の計画・結果クロスレビューを別主体で行い、Aの受入判断と区別する。

この対応表は例の解説である。実行指示文に同じ情報が保持されていれば、実案件で対応表と8欄を重複作成する必要はない。

## 条件によって行動が変わる判断例

下表は規則の適用を示す架空例である。必要な行だけを参照し、全例を毎回読み込ませない。

| 論点 | 条件 | 選ぶ行動 | 理由・避ける誤解 |
|---|---|---|---|
| 検証を終える | すべての受入条件に対応する選定済みの検証を実施して各条件を満たし、新しい具体的な回帰リスクもない | 証拠を記録し、定めた完了・受入処理へ進む | 原則3・4、9.4。「念のため」の無関係な試験を追加しない。必要な検証の省略でもない。 |
| 検証を追加する | 変更箇所に関係する具体的な不具合を検出し、現在の検証ではその影響を判定できない | 未達条件又は回帰リスクとの対応と実行権限を確認し、必要な検証だけを追加する。許可外なら該当操作を保留する | 原則5・20・26、9.4。検証の不足を放置しない。発見だけで全試験や対象外修正を許可しない。 |
| 次のカードへ進む | 同じ依頼内で次カードまで着手が許可され、前提証拠・必要レビュー・累積上限を満たし、選択した到達点への順序が妥当 | 必要な阻害条件を減らす次カード又は先に可能な受入確認へ進む | G6、6.9、9.4。一枚の局所完了だけで依頼全体を止めない。カード変更で上限をリセットしない。 |
| 次のカードを始めない | 今回の許可は文案提示までで、実装は人間の承認後と指定されている | 文案と判断材料を提示し、実装を始めず承認を待つ | 原則1・3、G6、9.4。上位目的への寄与を、後続作業の許可にしない。 |
| 証拠不足を扱う | 受入に必要な証拠がないが、許可済みの既存記録から確認可能 | その確認を行う。確認できなければ未評価と影響を記録する | 1.4、G7・G8、9.4。不足を架空の証拠で埋めない。不足だけで許可内確認を一律停止しない。 |
| 例と現状を区別する | 例には対象版や上限があるが、実案件の入力には記載がない | 例の値を使わず、未確認として権限・範囲・受入への影響を判定する | 1.3・1.4、4.5、9.5。例のもっともらしさは、実案件の事実又は許可の根拠にならない。 |

| 論点 | 条件 | 選ぶ行動 | 理由・避ける誤解 |
|---|---|---|---|
| 局所合格から次作業を選ぶ | 補助機能は合格したが、次に提案した拡張は選択した到達点の前提ではない | 拡張を後続残件とし、必要な前提又は先に可能な確認を選ぶ | 6.14。局所合格や発見だけでは次作業の必要性を証明しない。 |
| 新しい安全上の不足 | 現操作が許可外の保存先へ書き込む可能性を確認した | 影響する操作を止め、許可内で隔離境界を修正・確認し、順序を再判断する | 第7章、6.14。最初の前提一覧を守るために危険を放置しない。 |
| 利用量に欠測がある | レビュー側のトークンは取得不能だが、時間上限での継続が事前合意され、既存の費用・利用量上限への適用条件も満たす | 欠測を記し、その上限内で次の確認を判断する | 第8章。欠測はゼロではなく、時間はトークンの実測ではない。 |


## 読み込み量を増やさない使い方

カードを作成・改訂する際には、必要な書き方又は判断例だけを参照する。実行者へは、現在有効な完成カードと必要な正本・入力を渡す。実行時の具体的な誤解を解くために例が必要なら、その判断に関係する部分だけを添える。

既存のT02・T17・T22・T37・T49の通しの作例は、成果物の記載粒度を示す資料として保持する。本例は作業実行の判断関係を示すもので、既存の5作例を追加の必読文書へ変えない。
