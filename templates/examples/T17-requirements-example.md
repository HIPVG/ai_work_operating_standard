## 読む際の注意

この作例の人物記号、EX証拠ID、対象版、時間・費用・件数はすべて架空である。実案件へそのまま転記せず、実際の正本と許可に置き換える。参照するEX文書・証拠は架空の参照で、実ファイルはない。例の記述によって作業範囲は広がらない。5作例は別時点・別作業であり、同じIDがあっても通しの承認履歴にはならない。

## 共通8欄

| 欄 | 記入例 |
|---|---|
| C1 目的と期待結果 | 目的EX-V01 v2は、利用者が結果の根拠と未達条件を画面上で把握できること。今回は表示機能の要求案EX-R01 v1を作る。製品全体の自走機能や全Dayの設計確定は対象外。 |
| C2 対象と現状 | 入力は目的EX-V01 v2、表示対象のデータ項目メモEX-D01 v1、権限方針案EX-A01 v1。項目の定義は読んだ想定だが、現行UIの挙動は未確認。『既に表示できる』とは書かない。 |
| C3 決定・受入責任者 | Aが要求の決定・受入を担当、AI-Bが作成、別主体AI-Cがレビュー予定。予定のレビューを実施済みとしない。最終の機密開示判断はAが担当する。 |
| C4 許可・禁止と費用 | EX-W17 v1は既存入力に基づく要求案の作成を許可。2時間、追加課金0円。要求案に書いたUI操作、性能測定、API接続は今回実施しない。 |
| C5 主体と権限 | AI-Bは文書作成、AI-Cはレビューの役割案。製品の権限モデルは設計対象であって現在のAIの権限ではない。利用者別の開示範囲が未承認なので仮決定で公開しない。 |
| C6 検証と証拠 | 要求の検査可能性と上位目的との対応を机上確認する。後工程の実UI確認では結果ID・対象版・証拠参照の一致と欠落時表示を観測する計画。実証拠はまだない。 |
| C7 停止・復旧 | 要求間の矛盾・権限の不明点は該当要求を未決にし、許可内の他の案整理は継続する。要求確定はAの判断待ち。差戻し時はEX-R01の前版と差分を保存する。 |
| C8 結果と残課題 | REQ-01〜03を提案した想定。機密の開示条件、性能目標、最終カバレッジは未決。G4には『未承認の要求案』として渡す。実装着手可とはしない。 |

## 固有欄

| 欄 | 記入例 |
|---|---|
| 要求主体 | 研究担当は、一つの実行結果から何を根拠に判断したか追いたい。運用担当は、未達条件と次の行為が許可内か確認したい。双方を同じ『進捗表示』に丸めない。 |
| 機能 | 結果を選択すると、結果ID・対象版・証拠参照を表示する。証拠がない場合は『未確認』、未実施なら『未実施』とし、成功を既定値にしない。 |
| 受入 | 保存済みの結果ID・対象版と表示が一致し、欠落を欠落として示す。テストでID一致だけを確認して未達表示を省いた場合は受入条件を満たさない。 |
| 非機能 | 応答時間の閾値は同時利用数・データ量が未決のため未確定。機密を含む証拠の全文表示は権限方針の判断待ち。性能値を仮置きして承認済みにしない。 |
| 優先・範囲 | 初回対象は一作業種類の結果参照。全種類の網羅性は別要求REQ-03で扱う。REQ-01の成功はREQ-03の成功を意味しない。 |
| 矛盾と変更 | 追跡性のための詳細表示と、機密を見せない要求が衝突している。Aへ『要約のみ／権限別表示』の選択肢と影響を提示し、案の変更履歴を残す。 |

## この作例で確認すること

- 受入条件が『適切に』『高速に』だけになっていないか：上の共通欄・固有欄・明細を対応させて読む。
- 未確認を隠す代わりに、判断への影響と担当・時点を示している。
- 記載の厚みを保ちながら、追加実行を許可せず、既存の許可内の整理は止めていない。
- 作例の体裁を満たしても、実案件の証拠、権限、受入の代替にはならない。
