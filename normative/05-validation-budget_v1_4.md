## 7. テスト標準

| 変更 | 必須テスト | 追加条件 |
|---|---|---|
| 純粋ロジック | 単体テスト、関連回帰テスト | 状態又は外部入出力の追加時 |
| 状態機械 | 正常、拒否、終了、再開 | 再試行、時間超過、並列変更時 |
| アクセス制御・隔離実行環境 | 実際の主体による許可・拒否の確認 | 主体又は対象パス追加時 |
| 外部API・イベント | 実E2E、重複防止、失敗、後始末 | 非冪等、費用、副作用時 |
| UI | 実利用導線 | UI要件をAPI試験で代替しない |
| Git・実行環境操作 | 許可ファイル、コミット、遠隔`HEAD` | 統合、公開、権限変更時 |
| 長時間実行 | 定期状態通知、期限、孤児化、再開 | イベント源変更時 |
| AI評価 | 盲検、保存済み出力、切断、根拠性 | AIモデル、指示文、文脈変更時 |
| 証拠比較 | ハッシュ値、条件一致、測定値一致 | 過去成果物を援用する時 |

### 7.1 修正と試験の順序

- 不具合修正では、修正より先に元の失敗を再現するか、再現できない理由と観測計画を記録する。原因仮説を持たない場当たり的な修正を続けない。
- 新規又は変更した決定的な振る舞いは、可能なら期待する失敗又は受入条件を先に検査として表し、最小変更後に同じ条件で合格を確認する。
- UI、外部サービス、探索的なAI出力など、先行する自動試験が適さない場合は、実E2E、固定した観測条件、又は人間による読み戻しを代替証拠にする。試験の形式を目的化しない。
- 実装前の試験基準、実装後の試験結果、テスト自体の変更を分けて記録する。

### 欺瞞防止

- 独立確認を適用する場合は、受入基準と判定に使う検査を、受入時に実装担当が変更できる範囲から外す。初期の検査作成は第3.6節に従う。
- 固定後の受入基準又は独立確認用の検査を変更する場合は、別の管理主体による承認と変更理由を記録する。軽量開発の自己確認を独立確認と表示しない。
- テスト数の増加を品質向上とみなさない。
- 本番用の生成経路を通らない固定入力だけで接続を証明しない。
- 生の出力が空なら、変換部品で回答を作らない。
- 出力上限、指示文、AIモデルを結果後に変えた場合は別条件として記録する。
- 盲検評価では、評価者の指摘を対象AIモデルへ渡さない。
- `NOT EVALUABLE`を不合格又は合格へ変換しない。
- 過去成果物を現在条件の証拠へ登録する前に、来歴と条件を照合する。

変更前に、今回触れる入口、返却契約、識別子、副作用、隔離範囲のうち、受入判断に影響する境界を現行仕様又は計画と対応付ける。変更後は、その境界が成立する場合、拒否される場合、失敗する場合に必要なケースを確認する。関係しない境界の一覧作成や全試験の再実施は一律に求めない。今回の変更で生じた不具合は修正する。同じ境界の見落としによって再修正した場合は手戻りとして記録する。

## 8. 費用管理

作業にかかる費用と利用量は、作業カード又は既存の記録で確認できるようにする。費用が発生しない場合も、その確認結果を残す。費用のためだけに別の帳票を増やさない。

| 項目 | 内容 |
|---|---|
| 発生条件 | API、エージェント実行、保存、ダウンロード、人間作業 |
| 単位 | トークン、クレジット、分、GB、要求数、月額 |
| 請求主体 | 個人、組織、顧客、委託先 |
| 上限 | 作業、日、月、実行回 |
| 観測 | 利用量API、請求画面、ログ |
| 停止 | 予算制御、時間超過、停止操作、解約 |
| 状態 | 無料確認済、有料確認済、課金可能性あり、未確認 |

開発、指示作成、レビューに使った累積利用量と、製品の運用時に利用者が使う量を分ける。

- 既存の実行ログ又は利用量表示から、対象期間、作業、主体、単位、累積値、集計対象、欠測を確認する。
- 同じ応答を重複計上しない。カード、工程、継続ターン、担当が変わっても累積値をリセットしない。
- レビュー側の利用量は取得できる範囲で含める。取得不能な分は未確認とし、ゼロとしない。

入力・キャッシュ・出力トークンの実測値は、請求額やアカウント全体の利用枠消費と同じとは限らない。提供元が定めた単位と意味を保ち、根拠なく金額や利用枠へ換算しない。

正確な利用量を取得できない場合は、事前に許可された時間、呼出し数、作業量などの上限で該当作業を制御してよい。ただし、その上限値をトークン数や費用の実測値と報告しない。代替の上限を使っても、既存の費用・利用量上限は解除されない。残量の照合を要する操作で照合できなければ、その操作を止める。別の上限による継続が事前に合意されている場合は、合意した適用条件に従う。

作業を続ける前に、既存カードの「許可・禁止と費用」「停止・復旧」の欄又は正本への参照から、事前に合意した累積上限、残る許可範囲、次の判断時点、終了条件を確認する。委任された範囲内なら、作業順の変更や任意作業の保留を行ってよい。AIが新しい数値上限、支出、権限を独自に承認してはならない。境界に達した操作は止め、定められた担当へ判断を渡す。一定時間ごとの人間承認は一律に追加しない。

費用に関する最新の外部事実は、一次ソースと確認時刻を必要とする。特定案件の直接証拠は規範外資料の付録B・E17を参照する。費用提案は、根拠の矛盾が解消するまで保留する。

予算超過は観測結果を上書きしない。操作成功と予算警告を別の項目で保持する。
