# 必要な豊富さを確保するための50文書テンプレート集 v0.5

改訂履歴: 2026-09-26 初版／v0.2 作例・規模・引継ぎを調整／v0.5 運用標準とのクロスチェックを反映
状態: 任意採用TIPS／自己レビュー、利用効果は未評価
対象: AIを用いるシステム開発の成果物作成・レビュー・引継ぎ
適用例: 軽量PoC、中規模開発、大規模開発。規模は利用側の指定を入力とする。

## 位置付け

[運用標準](../01-ai_work_operating_standard_integrated_v1_0_2026-09.md)を正とし、[スタディ](../02-ai_artifact_sufficiency_study_v0_1_2026-09.md)の50文書を、選んで使える記入用紙と作例にした。新しいプロジェクト管理方法論や、全案件への50文書作成義務ではない。既存の顧客帳票へ必要な問いだけを取り込んでもよい。

AIは許可された作業範囲を最小化してよいが、目的、根拠、未決事項、リスク、判断条件、引継ぎを消してはならない。ただし、この記載要求を根拠に範囲拡大や追加検証を実施してはならない。既に許可された確認・修正・指摘対応はその範囲で継続できる。範囲・権限・費用・設計判断等の変更が必要なものは所定の判断先へ渡す。不足は推測で埋めず、影響と判断先を記録する。

## 読み方・使い方

1. 利用側が指定した規模・進め方と、案件の作業定義を入力として受け取る。運用標準に基づく適用判断・記録はPJ管理側の正本を参照し、TIPSで再認定しない。
2. 下表から今回の判断に必要な文書又は固有欄だけを選ぶ。未選択の文書に記入・不採用理由を求めない。
3. [共通骨格・品質基準](DESIGN.md)と選択したテンプレート、該当する作例をAIへ渡す。50文書を毎回一括入力する必要はない。
4. 既存の根拠だけで記入し、不明・矛盾・未評価を残す。共通8欄は一度だけ記入し、別票からは版・節を参照する。
5. 固有の問いと品質基準に照らして不足を確認し、判断・受入は案件の権限とレビュー体制に戻す。書式の完成だけで工程通過や製品完成にはしない。

軽量なら、例えばT02の目的、T05の境界、T17の受入条件、T32の実施範囲を一枚の既存作業カードへ取り込み、実施後の証拠はT37の表を短い結果欄へ統合できる。これは選び方の例であり、これらの独立ファイルを必須にしない。T01の憲章も軽量では尚可である。

規模は書き方の目安であり、リスク分類や統制の選定はPJ管理側が行う。供給側は、指定した進め方で成立しない条件が判明したら、根拠・影響・対応案を引き継ぐ。特にゲート通過用成果物では、障害・課題・懸念を省略せず、通過可否や持越し条件の判断へ渡す。規模や作業範囲を自動変更しない。
