# 50文書テンプレート集 — 共通設計・品質基準 v0.5

改訂履歴: 2026-09-26 初版／v0.2 作例の具体化とPJ管理への接続を調整／v0.5 運用標準とのクロスチェックを反映
状態: TIPS・テンプレート集の設計基準
対象: 選択したテンプレートの作成・記入・レビュー
適用例: 軽量PoC、中規模開発、大規模開発

## 1. 位置付け

[運用標準](../01-ai_work_operating_standard_integrated_v1_0_2026-09.md)が本リポジトリの規範、[スタディ](../02-ai_artifact_sufficiency_study_v0_1_2026-09.md)と本集は任意採用のTIPSである。顧客の管理体制に合わせ、必要な問いだけを既存帳票へ取り込める。採用後の案件上の必須欄・承認は、その案件の決定権者が定める。

50という数は既存のカタログとの対応数であり、50の公開書式を一対一で転載・検証したという意味ではない。公開資料の観点と運用標準を参照して独自に設計する。文書数・項目数・文字数は案件の合否条件にしない。

不明点の記録と、根拠を取得する行為の許可は別である。既存の許可範囲にある収集・確認・指摘対応は継続できるが、範囲・権限・費用・設計判断等の変更が必要なものは所定の判断先へ渡す。欄を埋めるための範囲拡大・追加検証は本集から許可されない。証拠不足は完了不可の理由になっても、許可済みの作業を一律停止させない。

| 分類 | ID | 中心となる問い | 代表テンプレート |
|---|---|---|---|

| B 調査・要求 | T11〜T20 | 何が分かり、何を満たせばよいか | T17 要求仕様書 |

## 3. 共通骨格

各文書は、管理ヘッダ、使う場面・統合先、共通記入欄、固有の問いと記入例、実務用の明細表、規模別の深さ、引継ぎとレビュー、悪い例、参考文献で構成する。

共通記入欄は次の8項目を運用標準9.1へ対応させる。一つの作業で複数テンプレートを使う場合、共通欄は一度だけ記入し、他の文書はその版・節を参照する。

| 欄 | 記載内容 | 薄い記入を防ぐ問い |
|---|---|---|
| C1 目的と期待結果 | 上位目的、今回決めること、対象外 | この文書が完成しただけで製品完成と扱っていないか |
| C2 対象と現状 | 入力・対象版・確認範囲・未確認 | 何を読めず、何に影響するか |
| C3 決定・受入責任者 | 作成、レビュー、検証、裁定、受入、権限根拠 | レビュー案を承認済みと扱っていないか |
| C4 許可・禁止と費用 | 依頼・作業カードの参照、範囲、上限 | 不足を埋める行為は既存の許可に入るか |
| C5 主体と権限 | 人・AI・環境・資源・操作 | 役割の名称と操作可能性を混同していないか |
| C6 検証と証拠 | 受入条件、方法、証拠、自己／独立確認 | 計画、報告、直接観測を区別できるか |
| C7 停止・復旧 | 境界、打切り、再開、戻し方 | 未達の全てを停止又は自動再試行にしていないか |
| C8 結果と残課題 | 実績、実施上の障害・課題・懸念、依存、未決、次工程 | 根拠・影響・対応案を誰のどの判断へ渡すか |

採用した欄は、内容・正本参照・理由付き該当なし・未確認のいずれかを記す。未選択の50文書を「該当なし」で埋める作業は不要。事実の状態は標準1.4、作業状態は1.6、レビュー判断は6.12を使い、TIPS独自の状態コードを追加しない。

## 4. 作例の設計

全50件に、固有の問いごとの記入例と、明細表の記入例を設ける。5代表には共通8欄まで埋めた通しの作例も付ける。作例はすべて架空で、数値・役割・証拠ID・日付は実案件の承認・測定を表さない。例示証拠は実ファイルとして生成しない。

作例は現実らしさではなく、判断に必要十分な豊富さを示す。条件・基準、根拠・結果、判断理由、残る障害・課題・懸念と引継ぎがつながればよい。架空の数値でも内部の整合は保つ。「未確認」を適切に残す例と、必要な情報が揃って採否・保留を判断できる例を使い分ける。実案件での有効性は、採用後に評価されるものであり、本書の作成だけでは実証しない。

## 5. 規模別の調整

規模は利用側・PJ管理側の指定を入力として扱う。本集は軽量・中規模・大規模に応じた書き方のTIPSであり、規模を認定したり、リスク分類・対応・受容の規則を定めたりしない。運用標準が求める適用判断・記録はPJ管理側の正本を参照し、TIPSで重複させない。

| 規模 | 使い方 |
|---|---|
| 軽量 | 既存の作業カード等へ必要な固有欄を統合する。T01憲章は尚可。目的・根拠・判断・残課題は短くても残す。 |
| 中規模 | 工程・役割をまたぐ要求、変更、証拠、判断の対応を示す。 |
| 大規模 | 複数領域・組織・提供版の依存と整合を追跡できる粒度にする。無関係な欄や50文書の全採用は要求しない。 |

指定された進め方では成立しない条件が判明したら、供給側は根拠・影響・対応案を既存の引継ぎ欄からPJ管理側へ提言する。規模、統制、費用、実施範囲を自動変更しない。例えば、軽量で開始した作業に別部門の受入が必要と分かったら、その判断依存を報告する。新しい「軽量認定票」は作らない。

「必須・推奨・尚可」はスタディの参考値であり、独立文書の作成命令ではない。案件の役割分離・権限・受入条件は運用標準とPJ管理側の決定に従う。

## 6. 品質基準

| ID | テンプレート集の確認点 | 合格の目安 |
|---|---|---|
| Q1 | 目的と範囲 | 使う判断、対象外、権限の参照先がある |
| Q2 | 内容の固有性 | 名称の置換だけでなく、その文書で必要な問い・明細表がある |
| Q3 | 作例の厚み | 条件・基準→根拠・結果→判断→残課題の接続が読め、注意書きだけで終わらない |
| Q4 | 事実の扱い | 架空例と実績が区別され、不明を肯定に置換しない |
| Q5 | 比例適用 | 利用側の規模指定に沿う記載深度と統合先があり、不成立条件はPJ管理へ提言する |
| Q6 | 権限 | 欄・参考文献・レビュー指摘が追加実行の許可にならない |
| Q7 | 工程接続 | 入力、出力、未決の判断先があり、G番号を取り違えない |
| Q8 | 正本と出典 | 運用標準への対応、参考文献の利用範囲、正本参照が明確 |
| Q9 | 完了判定 | 書式の充足、事実の確認、製品受入を別に扱う |
| Q10 | 配布品質 | 50IDの重複欠落、リンク切れ、表の列崩れがない |

本版の横断レビューは同じ作成主体による自己レビューである。書式の検査は意味の妥当性や顧客利用での効果を保証しない。効果は、採用案件での手戻り・引継ぎ不足・追加負担を観察して評価する。

## 7. ゲート報告への接続

工程の必須成果物と通過条件は運用標準第5章が定める。下表は選択の例であって、工程ごとの必須テンプレートを追加するものではない。軽量開発では標準3.6の統合を維持する。

| 工程 | 主な判断 | 選べる文書の例 |
|---|---|---|
| G0 受付・入力完全性 | 対象・入力・決定権が揃うか | T04、T05、T08、T41、T49 |
| G1 現状調査 | 何が確認済みで何が不明か | T12、T16、T43 |
| G2 目的・要求定義 | 何を満たすべきか | T02、T11、T17、T19、T20 |
| G3 外部調査・実現性 | どの方式がどの条件で成立するか | T03、T12、T21、T45 |
| G4 基本設計・制御設計 | どう構成し失敗を扱うか | T22〜T29、T31、T42、T49 |
| G5 実装計画 | 何をどの順序・権限・証拠で行うか | T30、T32、T36 |
| G6 実装 | 範囲内で何を変え何が残ったか | T33、T34、T35 |
| G7 検証 | 条件ごとの証拠が成立したか | T20、T37、T38、T44、T47、T48 |
| G8 受入・送達 | 誰が何を受け入れどこまで届いたか | T38、T39、T40、T46 |
| G9 運用・学習 | 効果・品質・費用を踏まえてどうするか | T10、T33、T50 |

案件で運用標準6.12の段階レビュー記録を用いるときは、選択した文書又は既存の議事録へ次の情報を統合する。T31だけでなく、要求・計画・受入などのレビューにも使える。自己確認だけでこの決定欄を承認済みにしてはならない。

| 決定記録の欄 | 記入欄 | 架空の文例 |
|---|---|---|
| 工程・対象・版・範囲・日時 | ［記入］ | G4／設計EX-D01 v2の欠落表示／例示日D1。認証の再設計は対象外。 |
| 参加役割・欠席した必須役割 | ［役割表の版を参照］ | 技術担当B、レビューC。受入責任者Aは欠席。Cに最終承認権はない。 |
| 確認事項・障害・課題・懸念 | ［根拠と実施・ゲート判断への影響］ | REQ-01に対して証拠欠落時の表示が未定義。EX-D01 v2の表示節を根拠とする。 |
| 対応責任者・期限・未解決 | ［記入］ | BがG5の着手判断前に欠落表示を追記する案。期限の暦日はAとの調整待ち。 |
| 決定結果・決定権者・権限根拠 | ［提案と実際の決定を分離］ | Cは条件付き承認を提案。Aの決定は未了。Cの提案を継続許可にしない。 |
| 条件・有効範囲・未達時の状態 | ［記入］ | 提案条件は欠落表示の確定。解消前は該当実装へ移らない。他の許可済み作業への影響は別判断。 |
| 次工程条件・再レビュー・判断先 | ［記入］ | Bの修正版をCが再確認しAへ提示。裁定不能なら役割表の委任範囲に従いAへ戻す。 |

ゲート通過用成果物では、実施上の障害・課題・懸念を省略しない。既存欄に根拠・影響・対応案・判断先・時点を記し、正本参照でもよい。未解消なら全て自動停止するのではなく、通過可否・継続範囲・持越し条件を権限のある判断者へ渡す。追加調査や対策の実行は別の許可に従う。

共通8欄は事実と実施境界を保持し、この記録は工程の決定を保持する。両者を同じ文書へ統合してもよいが、作成・レビュー・承認・実行・受入の違いは消さない。
