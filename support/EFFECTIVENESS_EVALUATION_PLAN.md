# 効果評価計画 v0.5

改訂履歴: 2026-09-26 初版／v0.2 選択補助の条件・厚みの観察を追加／v0.3 保存した候補一覧の扱いを追記／v0.5 公開版として整理／2026-10-05 作業カードの記述と体系の整合を整理／2026-10-05 クロスレビューと効率の議論を統合／2026-10-06 次作業の選定・変更境界・累積利用量を具体化

状態: 規範外の評価計画

対象: テンプレート又は運用標準を小規模に採用した案件

## 1. 目的と限界

目的は、本体系が実務上の曖昧さ、手戻り、引継ぎ不足、証跡欠損を減らすかを、小さな採用単位で観察することである。採用前に効果を断定せず、少数案件の結果を一般化しない。

比較対象、測定方法、個人情報・顧客情報の扱い、追加調査の許可は案件の決定権者が定める。本計画は調査・計測・保存を許可しない。

## 2. 最小の観察単位

案件又は変更単位ごとに、採用した問い・統合先と、判断に影響した選択理由を残す。未選択の50文書すべてに不採用理由を求めない。可能なら、導入前後で同じ定義を使う。比較不能、未記録、外部要因が大きい場合は、そのまま`NOT EVALUABLE`又は未確認として扱う。

HTML選択補助を用いる場合は、使用版、主要なGiven Conditions、未確認の条件、選んだLoose／Medium／Tight、実際に採用した問いを既存の記録へ追記できる。保存ボタンで候補一覧と回答をJSON／CSVへ出力できるため、選択時点の記録として参照してもよい。自動保存は行わない。出力は候補であり、実際に採用した問いや受入結果は案件側の記録で確認する。厚みは案件規模・リスク区分とは別の変数として扱い、候補数の多寡自体を品質や効果の指標にしない。

| 観察項目 | 定義の例 | 混同しないもの |
|---|---|---|
| 手戻り | 受入条件、範囲、設計の不一致により、合意済みの作業を戻した回数・理由 | 通常の反復、未許可の追加要求 |
| 引継ぎ不足 | 次工程・担当者が、既存記録だけでは判断できず追加確認した件数・理由 | 新規の探索的改善 |
| 証跡欠損 | 受入時に必要とされた根拠、版、責任、結果が追跡できなかった件数 | 事後に任意で増やした資料 |
| 追加負担 | 記録・レビュー・修正に要した時間又は主観的負担 | 成果物のページ数だけ |
| 境界逸脱の抑止 | 範囲・権限・費用に関する不明点を、実行前に判断先へ渡せた事例 | エージェントや作業者の自己申告だけ |
| 選択補助の適切さ | 必要だったのに候補外だった問い、不要だった候補、条件を誤解した事例と理由 | 表示件数の増加、Tightの選択自体 |

### 作業カードの表現と判断例を観察する場合

新旧を比べる場合は、目的、受入条件、許可、入力、モデル・設定及び上限を可能な範囲でそろえ、異なる条件は記録する。表現変更による効果と、条件変更による差を混同しない。既存の許可・費用枠で得られる記録を用い、比較のための追加モデル呼出し、モデル変更又は有料評価を本計画から開始しない。

| 観察項目 | 判断に用いる事実 |
|---|---|
| 範囲外作業 | 現在の未達条件・具体的回帰リスク・許可に対応しない操作を開始したか |
| 不要な停止 | 後続まで許可され、前提・必要レビュー・上限も満たすのに停止したか |
| 受入条件の見落とし | 元の条件を検査せず、又は満たさず合格としたか |
| 例の誤用 | 例の対象、数値、権限又は証拠を実案件の事実として用いたか |
| 追加負担 | 読込み・指示作成・報告・手戻りの時間と、取得できる範囲の入出力量がどう変わったか |

必要なレビューによる欠陥検出や、許可された局所作業の完了を失敗として数えない。時間・使用量の記録がなければ遅延又は費用削減を断定しない。低位モデルの結果がなければ、その効果は未評価とする。対策の有効性は運用標準の`EFFECTIVE`に対応する証拠で判断し、外部操作の`VERIFIED`とは分ける。

### クロスレビューと効率を同時に評価する

運用標準6.13・6.14の実効性は、チェック欄の充足とは別に評価する。既存の事例・保存証拠と許可枠を用い、元条件と実体に照らして、無根拠の完了、不要な追加、許可内の未完終了を見逃さないか、正当な局所完了・必要な品質作業を誤棄却しないかを確認する。レビュー用の負例は例であると識別し、実運用の証拠と混ぜない。

レビュー担当には元条件と必要な実体を渡す。実施者の要約だけで正答を決めず、指摘数・PASS数・文書数を品質指標にしない。既存予算で確認できない場合は未評価とし、新規課金・上位モデルの採用・比較実験を本書から開始しない。

効率は、計画、実施、確認、報告、待機、手戻りを含む総経過時間と使用量で比較する。ACTIVE_WORKから除く待機も利用者の処理時間には含める。不要な追加の誤承認、虚偽完了・回避の見逃し、必要作業の誤棄却が増えていないかを同時に見る。比較条件が不足すれば因果効果を断定せず、低位モデルの記録がなければ効果を一般化しない。

## 3. 記録例

| 項目 | 記入例（架空） |
|---|---|

## 4. 判断と改訂

複数の観察で、特定の問いが繰り返し役に立たない、過重、又は誤解を招くと分かった場合は、根拠・影響・代案を改訂候補として記録する。単発の成功・失敗、文書の存在、テスト終了コード、自己報告だけで本体系の効果を`EFFECTIVE`としない。外部操作の確認状態`VERIFIED`を、体系の効果判定として用いない。

案件の受入結果と、標準・テンプレート体系の有効性評価は別の判断である。

## 2026-10-06改訂の観察範囲

既存のカード・レビュー・実行記録から、局所合格後の次作業が選択した到達点の阻害条件を減らしたか、より小さい操作又は先に可能な確認があったか、新たな不足が根拠なしに追加実装へ変わったかを確認する。変更境界の見落としで自ら生じさせた再修正は、必要な不具合修正を妨げず手戻りとして扱う。

開発・指示作成・レビューと製品運用時の利用量を分け、単位、集計範囲、重複・欠測、累積上限との照合を記す。トークン実測から請求額又はアカウント利用枠を推定しない。観測不能な項目は未確認とし、既存記録の確認を専用基盤の開発へ広げない。

この改訂は論理上の制御関係の明確化であり、処理効率又は低位モデルでの品質改善の実証ではない。評価のための追加実験・利用量・費用は既存の許可と上限に従う。
